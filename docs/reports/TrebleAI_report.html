TrebleAI: AI-Powered Self-Learning Music Platform

An architectural capability demonstration of automated sheet music parsing, deterministic structural feature extraction, and multi-tool LangChain ReAct tutoring agents.

Project Narrative & Core Highlights

  • Designed and developed TrebleAI, an AI-powered self-learning music platform that enables users to independently learn and practice sheet music through intelligent automation, reducing reliance on instructors and tutorial videos.
  • Engineered an end-to-end music processing pipeline using Audiveris, music21, MIDI generation, and FluidSynth to convert uploaded sheet music into synchronized audio and interactive notation.
  • Built AI-powered tutoring agents using LangChain with multi-tool integration and structured JSON outputs to answer questions about uploaded scores, retrieve music theory, and provide personalized learning assistance.
  • Architected a full-stack application using FastAPI background tasks, Next.js, TypeScript, and PostgreSQL, integrating AI tutoring, intelligent search, synchronized sheet music rendering, animated piano visualization, and real-time playback into a unified platform.

Agentic Tutor (LLM + LangChain ReAct)

TrebleAI's AI-powered tutor is built around a custom Reasoning-Action (ReAct) loop implemented with LangChain. Rather than functioning as a standard conversational chatbot, the tutor acts as an orchestration engine. It retrieves structural attributes from the deterministic music engine and binds to external tools, choosing when to query the local PostgreSQL-backed reference library for definitions versus executing fallback searches on the web.

Voice-Leading Violations for Sample Piece B:

The parser has detected voice-leading violations in your uploaded score:

  • Measure 20: Parallel Perfect Fifth between F3 and C4
  • Measure 22: Parallel Perfect Octave between E3 and E4

Theoretical Rationale:
Perfect fifths and octaves represent high acoustic consonance. In polyphonic writing, if two voices move in parallel perfect intervals, their harmonic independence is lost. The two lines temporarily merge into a single acoustical line, which violates voice separation principles.

Suggested Keyboard Practice Routines:

  1. Outer-Voice Isolation: Practice playing only the bass and soprano voices together. Parallel octaves/fifths are visually and aurally easiest to spot in outer voices.
  2. Sing-and-Play Technique: Sing the lower voice line while playing the upper voice on the keyboard to develop independent auditory tracking.
  3. Contrary Motion Alteration: Resolve the voices in contrary motion (e.g., if one voice moves up, transpose the resolving voice downward).

System Architecture & Interfaces

TrebleAI's frontend architecture is divided into three core user interfaces, which interact with a consolidated backend pipeline handling OMR transcription, deterministic parsing, and multi-tool AI orchestration.

1. Practice Agent

The interactive practice dashboard. Users upload scanned sheet music files to generate dynamic vector notation (rendered via OpenSheetMusicDisplay), synchronized audio playback, and a side-car AI agent contextualized with the analyzed score metrics.

2. Theory Assistant

A full-screen interactive study interface. The general LangChain tutor answers open-ended music theory queries, scale or chord formulas, and historical concepts, dynamically generating follow-up prompts.

3. Music Library

The database-driven management page. Stores user history, manages uploaded scores, houses cached analysis reports, and supports search indexes of scales, intervals, and chords stored in a relational PostgreSQL schema.

Practice Agent: Integration & Ingestion Guide

The Practice Agent page acts as the primary pipeline orchestrator. It establishes a multi-layered ingestion workflow to process notation files and initialize the LangChain tutor with local context.

1

File Upload & Format Resolution

The client uploads scanned sheet music (PDF/PNG/JPEG) or structured XML files. Scanned images are transferred to a FastAPI background worker queue. OpenCV performs adaptive thresholding to eliminate background gradients and deskews the image boundaries, ensuring optimal Audiveris layout reading.

2

Optical Notation Transcription (OMR)

Audiveris parses the preprocessed binary image to resolve staves, pitches, and durational values. It generates a MusicXML payload, which is ingested by a python-based music21 stream parser. The parser structures the notation elements into a relational hierarchical tree cache.

3

Deterministic Feature Parsing & Synthesis

The backend extracts key signatures, modal overlaps, chord structures, modulations, and voice-leading violations. In parallel, a MIDI file is synthesized and mapped into standard audio files (WAV) via FluidSynth using SoundFonts, serving as synchronized audio playback for the interactive Next.js viewer.

4

Tutor Seeding & Interactive Practice

The extracted music analysis metrics are serialized into a JSON context envelope. When the user loads the score, this context is loaded as system prompt parameters for the LangChain agent. The student can click on specific measures, trigger audio loops, or chat directly with the context-aware coach to get targeted scale exercises and theory concepts.

Music Analysis Engine (Deterministic Infrastructure)

Before triggering LLM requests, TrebleAI runs the parsed score stream through a rule-based parser. This engine executes deterministic music theory algorithms to extract architectural attributes, separating rule-based processing from generative AI layers.

Analysis Extractions

  • Key Center Profiling: Computes pitch-class presence ratios to identify key signatures and shifts.
  • Modal Overlaps: Computes Jaccard similarity indices between pitch distributions and diatonic modes.
  • Structural Audit: Scans voice transitions for perfect fifth and octave voice-leading violations.
  • Rhythmic Mapping: Evaluates syncopations and durations to compile rhythmic motif matches.
  • Technical Profiling: Generates scale fingering recommendations via heuristic rules.

Key Learnings & Challenges

  • OMR Noise Control: Optical Music Recognition has high error propagation. Scanned page skewing or low-contrast inputs trigger pitch offsets in Audiveris, causing errors in key extraction. Incorporating OpenCV adaptive thresholding and binarization significantly reduced parsing noise.
  • LLM Structured Parsing Failures: Under complex multi-tool execution paths, LLM engines sometimes violate structured output schemas. We resolved this by building a custom regex fallback parser in agent.py to extract valid JSON blocks from unstructured message streams.
  • FluidSynth Audio Generation Latency: Synthesizing WAV files from MusicXML streams can block the main request thread. To resolve this, we offloaded audio rendering to FastAPI background tasks and cached the generated analysis report per session so repeat requests are served without reprocessing.

Final Approach & Summary

TrebleAI bridges the gap between text-based music study and practical execution by integrating a deterministic processing pipeline with a LangChain-based tutoring agent. By parsing inputs into structured streams, extracting rule-based music descriptors, and passing these descriptors as structured context into a multi-tool ReAct agent, we prevent tutor hallucinations and provide students with a context-aware practice companion. The resulting pipeline enables students to receive reliable, context-aware instruction based directly on their uploaded sheet music.
